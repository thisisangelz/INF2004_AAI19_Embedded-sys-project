Run lifecycle main()

From power-on to result, in order

  1. Power onInit log, motors, IMU, buzzer. Print the build banner.motion · run_report
  2. Wait for GP20GP21 here replays the previous run over USB.report_replay
  3. Start beepOpen a fresh flash log. GP21 now means STOP, latched.report_begin · motion_arm_stop
  4. Retry IMUA failed power-up I2C read gets one more try, motors off.motion_init
  5. Colour sensorOptional. Without it, BLE alone decides arrival.colour_sensor_init
  6. Gyro calibrationSteady tone. Keep the robot still.motion_calibrate · CUE_CALIBRATING
  7. Radio upWi-Fi station mode, then Bluetooth within 10 s.cyw43_arch_init · payload_client_init
  8. ApproachSearch, steer, transfer. One beacon, or two on a route.run_route
  9. ResultRising beeps for a payload, falling beeps for a fault.completion_sound · CUE_FAULT
  10. Close the logFault list, final page. Never restarts by itself.report_faults · report_finish

Calibration runs before the radio starts, so the long Bluetooth start-up never looks as if GP20 did nothing.

Wi-Fi line search line_search.c · wifi_sampler.c

A line ends when the signal drops three times

Step sizes

500 ms on the floor
250 ms once the mat is seen
100 ms within two rings of arrival

Measuring

  • Each reading is two batches of five scans, so one bad scan can't end a line.
  • Signal codes use 7 bits: −1 to −126 dBm, plus "missing".
  • A rise of 6 dB that then flattens for 2 stops triggers an early side probe.
  • After an early probe, a side goes first only if it beats the best point by 3 dB. Otherwise the robot carries straight on.
Arrival colour_sensor.c · colour_mat.c

The colour sensor decides when the robot has arrived

Arrival needs all of these

  • A lighter surface of the same mat seen earlier (white edge or an outer ring).
  • All 3 stationary readings on the arrival ring or darker.
  • BLE shows the beacon at −85 dBm or stronger.

Depth scale

  • 0 floor, 1 white edge, 2 to 7 for rings 1 to 6.
  • Ratios G/R and B/R tell the mats apart, so other beacons' mats read as floor.
  • 3 failed checks in a row turn the sensor off. BLE then needs −58 dBm.

Assessment

Solid foundations, one overloaded file

Sound

  • Each piece of hardware has its own module.
  • Pure logic is split out and tested on a PC.
  • Shared data has one writer or a lock. No races found.
  • Fixed memory, no malloc, limits raise faults.
  • Logs survive power-off and are CRC-checked.

Weak

  • getting_there.c is 1,444 lines with about 16 shared flags.
  • Navigation stages are implicit, with no state machine.
  • Tests include the .c file and read its private variables.
  • Six build variants multiply untested paths.

Next

  1. Do a short run on the robot and check the dashboard still reads the log.
  2. Split route, mat approach and search out of getting_there.c.
  3. Make the approach stages an explicit state machine.
  4. Test stages through their interfaces, not private variables.
